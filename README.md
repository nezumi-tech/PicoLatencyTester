# PicoLatencyTester

PicoLatencyTesterは、VRChatなどのVRアプリケーションにおいて、PICO Connect（PicoStreamingMicrophone）のオーディオストリームが継続的に消費されない場合に発生する「マイク遅延の蓄積問題」を客観的に検証・計測するためのWindows向けソフトウェアです。

基準となるマイク（有線マイクなど）と、テスト対象のマイク（PicoStreamingMicrophone）の音声を左右のチャンネルに分離して同時に録音し、WAVファイルとして出力します。録音待機中はオーディオデバイスを完全に解放する仕様となっており、意図的にバッファを詰まらせて遅延を再現することが可能です。

## 主な機能
* **2チャンネル同時録音**: LチャンネルとRチャンネルに別々のオーディオデバイスを割り当て、完全に同期したステレオWAVファイルとして記録します。
* **デバイスの完全解放**: 録音停止時はNAudioのインスタンスを破棄し、デバイスのキャプチャを完全に停止します。これにより、PICO Connect側のバックログ蓄積条件を正確に再現できます。
* **VRChatログ監視連動（自動録音）**: VRChatの出力ログ（`output_log_*.txt`）をリアルタイムで監視し、ワールドへのJoin（`Entering Room:`）を検知して自動的に10秒間のサンプル録音と連番保存を行います。

## 動作環境
* Windows 10 / 11
* .NET 10.0
* VRChat（自動録音モードを使用する場合）

## 使い方

### 手動録音モード
1. ヘッドセットをPCに接続し、PICO ConnectおよびSteamVRを起動します。
2. アプリケーションを起動し、**L Channel (Top)** に基準となる遅延の少ないマイク（例：PC直結のマイク）を選択します。
3. **R Channel (Btm)** にテスト対象の `PicoStreamingMicrophone` を選択します。
4. 「録音開始」ボタンをクリックして音声を吹き込み（手を叩くなどのインパルス音が最適です）、「録音停止」をクリックします。
5. 「プレビュー」で確認するか、「手動保存」でWAVファイルとして任意の場所に保存します。

### 自動録音モード（VRChat連動）
1. VRChatを起動した状態で、PicoLatencyTesterを起動します。
2. L/Rチャンネルのデバイスを設定します。
3. **「自動録音モード」** のチェックボックスをオンにします。画面下部のステータスに現在監視中のログファイル名が表示されます。
4. VRChat内で別のワールドへ移動（ロード）します。
5. ワールド参加が検知されると、5秒の安定化待機後にビープ音が鳴り、10秒間の自動録音が開始されます。
6. 録音完了後、再びビープ音が鳴り、実行ファイルと同じ階層の `AutoRecords` フォルダ内に `Record_001.wav` のように連番で自動保存されます。

## レイテンシの検証ワークフロー

本ソフトウェアを使用して、PICO Connectのマイク遅延が蓄積する現象を検証する標準的な手順です。

### 1. ベースラインの測定（正常時の確認）
遅延が発生していない初期状態でのタイムラグを測定します。
* PICO Connectを起動した直後に、手動モードで数秒間録音を行い、WAVファイルを保存します。
* 波形編集ソフト（Audacityなど）や解析スクリプトを用いて、L/Rチャンネル間の初期のズレ（通常は数十ms以内）を確認します。

### 2. 遅延蓄積条件の再現
オーディオ処理タスクがブロックされ、データが蓄積する状況を作り出します。
* PicoLatencyTesterで録音を行わず、**「待機中 (デバイス完全解放済み)」** の状態にしておきます。
* VRChat内で、別のワールドへの移動を複数回（3〜5回程度）繰り返します。この際、ビデオストリームの破棄・再構築が内部で発生し、これが音声処理を遅延させるトリガーとなります。

### 3. 事後測定と遅延の確認
ワールド移動によって蓄積したバックログ（遅延）を測定します。
* 再度「録音開始」をクリックし、アタック音（拍手など）を鳴らして録音・保存します。
* 保存したWAVファイルの波形を確認し、Rチャンネル（PicoStreamingMicrophone）のアタック音がLチャンネルから数百ミリ秒〜1秒程度遅れて記録されていれば、問題の再現は成功です。

### 4. ワークアラウンド（対策）の有効性検証
遅延を防止するワークアラウンドが機能しているかを検証します。
* PICO Connectを再起動して遅延をリセットします。
* VB-Cable等の仮想オーディオデバイスとWindowsの「このデバイスを聴く」機能などを利用し、`PicoStreamingMicrophone` をバックグラウンドで常に消費（ドレイン）し続ける状態を作ります。
* 上記の「2. 遅延蓄積条件の再現」と「3. 事後測定」を再度実行し、複数回のワールド移動後でも遅延が増大していないことを確認します。
